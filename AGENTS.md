# AGENTS.md

## Project Context

Сайт Федерации воркаута Забайкальского края.

Это современный промо-сайт спортивной федерации: энергичный, дерзкий, визуально сильный, с акцентом на движение, спорт, дисциплину, события, тренировки и сообщество.

Проект сейчас разрабатывается как frontend на Next.js. В будущем сайт будет связан с Directus как headless CMS, но Directus пока не подключать без отдельной задачи.

## Tech Stack

- Next.js
- TypeScript
- React
- SCSS Modules
- Future CMS: Directus

## Main Goal

Развивать сайт в рамках уже существующей визуальной системы и делать код так, чтобы проект было легко масштабировать: добавлять новые секции, страницы, интеграции, данные из CMS и повторно используемые UI-компоненты.

Любой новый блок должен выглядеть как часть текущего сайта, а не как случайный шаблонный landing page block.

## Design Direction: Kardo-inspired Workout Federation

Визуальный ориентир — [kardoaward.com](https://kardoaward.com/). **Не копировать сайт напрямую**, а перенимать принципы и адаптировать под федерацию воркаута Забайкальского края.

### Принципы (что брать с референса)

- крупная агрессивная типографика;
- спортивная энергия и ощущение силы;
- фестивальный / соревновательный вайб;
- плотные hero-секции с сильным первым экраном;
- контрастные блоки (чёрный / белый / красный);
- асимметричные композиции, а не ровные «коробки»;
- большие карточки с понятной иерархией;
- динамичные сетки и визуальный ритм между секциями;
- ощущение движения, улицы, соревнований и живого события;
- минимум «корпоративной чистоты» — сайт как **современное спортивное событие**, а не шаблонный сайт федерации.

### Обязательные правила для агента и новых блоков

1. **Любой новый блок** должен продолжать текущую дизайн-систему проекта (`@shared/ui`, токены, `Typography`, существующие паттерны секций).
2. **Не использовать** шаблонные секции «иконка + заголовок + текст» и однотипные трёхколоночные «фичи» без характера.
3. **Не делать** мягкий SaaS / UI-kit / agency-стиль: скруглённые «милые» карточки, пастель, стекло ради красоты, generic-иллюстрации.
4. **Использовать** крупные заголовки, короткие мощные тексты, плотную но читаемую композицию; фото — часть сетки, не просто прямоугольник сбоку.
5. **Основные цвета:** чёрный, белый, красный. Серый (`#f3f3f3`, `#f4f4f4`) — только как технический фон секций и карточек, не как «брендовый» цвет.
6. Блоки должны ощущаться **спортивно, дерзко, современно** — как промо турнира или фестиваля, а не как отчёт НКО.
7. **Перед созданием нового блока** сначала проанализировать уже существующие секции: отступы (`section-stack` / `--section-gap`), типографику, карточки, `SectionTag`, тёмные/светлые полосы.
8. **Новый визуальный приём** (декор, сетка, акцент) допустим только если совместим с референсом Kardo и уже реализованной стилистикой проекта — не вводить чужой визуальный язык.
9. **Анимации** — усиливать динамику (hover, раскрытие, лёгкий сдвиг карточки), но не превращать сайт в «цирк»: без бесконечных параллаксов, без лишних autoplay-эффектов.
10. **Контент** — по-русски, коротко, уверенно; без канцелярита, воды и пафосных штампов («уникальная возможность», «инновационный подход»).

### Чеклист перед сдачей секции

- [ ] Секция узнаваема как часть **этого** сайта, а не Bootstrap/Tailwind UI kit.
- [ ] Есть контраст: тёмная полоса / светлая / красный CTA или акцент — не всё серое и ровное.
- [ ] Заголовок и подзаголовок читаются с расстояния; body не превращён в простыню.
- [ ] Отступы согласованы с `--section-gap` и сеткой 8/4 (см. ниже).
- [ ] Типографика через `Typography`, без случайных `font-size` в SCSS.

## Visual System

Основные цвета:

- black
- white
- red

Правила:

- Красный использовать как сильный акцент, а не раскидывать случайно.
- Чёрный использовать для мощных контрастных блоков, hero, карточек, CTA.
- Белый использовать для чистых секций с большим воздухом.
- Не делать скучный корпоративный стиль.
- Не делать generic SaaS / startup / agency дизайн.
- Не использовать случайные пастельные цвета.
- Не использовать градиенты, если они не поддерживают текущую стилистику.
- Не добавлять лишние тени, glassmorphism и “красивости ради красивостей”.
- Не использовать размытые красные «ореолы» (`radial-gradient` blobs) — они выглядят дёшево; акцент красным — через плашки, линии, типографику, `--general-red-gradient` на CTA.
- Декоративные элементы допустимы (звезда, `SectionTag`, `Corners`, водяной знак, сетка на фоне), но они должны поддерживать спортивную айдентику проекта.

## Layout Style

Для секций использовать:

- крупные заголовки;
- короткие смысловые текстовые блоки;
- карточки с понятной иерархией;
- асимметричные сетки;
- крупные фото;
- декоративные элементы;
- CTA-блоки;
- бейджи / лейблы;
- аккуратные подписи;
- плотную, но читаемую композицию.

Не делать:

- ровные скучные блоки “заголовок + текст + 3 карточки” без характера;
- шаблонные Bootstrap-подобные секции;
- однотипные карточки без визуального ритма;
- большие простыни текста;
- дизайн, который не похож на текущий сайт.

## Отступы и размеры (сетка 8 / 4)

- **Вертикальный ритм страницы:** секции оборачивать в `SectionStack` (класс `section-stack`): `gap` и нижний отступ — **`--section-gap` (160px)**. Hero (чёрный первый экран) — только там, где нужен плотный вход. Страницы без hero — `offset="header"` (`section-stack-offset`, `--page-offset`), чтобы контент не заехал под шапку. Цветные полосы — `section-inset`. Не дублировать ритм своими padding/margin и не использовать bleed.
- **Отступы и интервалы** (`margin`, `padding`, `gap` и т.п.): по возможности значения в `px` **кратны 8** (8, 16, 24, 32, 40…). В крайнем случае — **кратны 4** (например 4, 12, 20), если иначе не сходится с макетом или сеткой.
- **Кегль** (`font-size` в `px`): та же логика — в первую очередь кратность **8**, при необходимости **4**. Случайные 13/17/19 без причины из макета не размножать.
- Исключения допустимы, если так зафиксировано в макете или без них не собрать композицию — но по умолчанию держаться восьмёрки.

## Типографика

- Управление шрифтами на интерфейсе — **всегда через `Typography`** из `@shared/ui`: вариант (`h1`, `h2`, `body`, `bodyLarge` и т.д.), тон, при необходимости `as`. Не задавать текстовым блокам произвольные `font-family`, `font-size`, `font-weight` в SCSS или инлайне, если это не осознанное исключение (например, логотип или единичный декоративный элемент).

## Code Style

Писать чистый, современный, поддерживаемый код.

Общие правила:

- Использовать TypeScript.
- Использовать React functional components.
- Использовать named exports.
- Не использовать `export default` для компонентов, если это не требуется Next.js.
- Использовать typed props.
- Не использовать `any` без крайней необходимости.
- Не смешивать бизнес-логику, верстку и подготовку данных в одном месте.
- Не дублировать большие куски JSX.
- Выносить повторяющиеся элементы в отдельные компоненты.
- Не вводить UI-библиотеки без явной задачи.
- Не подключать лишние зависимости без необходимости.
- Не писать код “на один раз”, если очевидно, что блок может развиваться.

## Component Rules

Компоненты должны быть:

- небольшими;
- читаемыми;
- переиспользуемыми там, где это оправдано;
- с понятными props;
- без лишней абстракции.

Пример структуры компонента:

```tsx
import styles from "./SectionName.module.scss";

type SectionNameProps = {
    title: string;
    text?: string;
};

export const SectionName = ({ title, text }: SectionNameProps) => {
    return (
        <section className={styles.section}>
            <div className={styles.container}>
                <h2 className={styles.title}>{title}</h2>
                {text && <p className={styles.text}>{text}</p>}
            </div>
        </section>
    );
};
